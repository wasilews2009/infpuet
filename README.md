# База знань ІЦ ПУЕТ

Інформаційна система Інформаційного центру Полтавського університету економіки і торгівлі: облік техніки по аудиторіях, ремонти, склад, програмне забезпечення, звіти, користувачі з ролями, чати й форум, журнал змін і резервні копії.

Сторінка працює як звичайний сайт на GitHub Pages. Спільна база даних і облікові записи зберігаються в безкоштовному проєкті Google Firebase.

## Файли

| Файл | Призначення |
|---|---|
| `index.html` | Сама система. Оновлюючи систему, замінюйте лише цей файл. |
| `firebase-config.js` | Налаштування підключення до вашого проєкту Firebase. Заповнюється один раз. |
| `firestore.rules` | Правила безпеки бази. Вставляються в консоль Firebase. |

Якщо `firebase-config.js` не заповнено, сторінка працює в локальному режимі: окрема база в браузері кожного користувача, без спільних даних.

## Налаштування Firebase (один раз, близько 15 хвилин)

1. Відкрийте https://console.firebase.google.com, увійдіть обліковим записом Google і натисніть **Create a project**. Назва, наприклад, `ic-puet`. Google Analytics можна вимкнути.
2. **Вхід користувачів.** Меню **Build → Authentication → Get started → Sign-in method → Email/Password → Enable → Save**.
3. **База даних.** **Build → Firestore Database → Create database**. Розташування: `eur3 (europe-west)`. Режим: **production**.
4. **Правила безпеки.** У Firestore Database відкрийте вкладку **Rules**, замініть весь текст вмістом файлу `firestore.rules` і натисніть **Publish**.
5. **Налаштування для сторінки.** **Project settings** (шестерня) → **General** → **Your apps** → значок `</>` (Web). Зареєструйте застосунок (Hosting не потрібен). Скопіюйте значення з блоку `firebaseConfig` у файл `firebase-config.js` замість слів `ВСТАВТЕ_...`.
6. **Дозволений домен.** **Authentication → Settings → Authorized domains → Add domain**: `ВАШ-ЛОГІН.github.io`.

## Публікація на GitHub Pages

1. Створіть репозиторій на GitHub і завантажте в нього `index.html`, `firebase-config.js` (і за бажанням `firestore.rules`, `README.md`).
2. **Settings → Pages → Build and deployment → Deploy from a branch**, гілка `main`, папка `/ (root)` → **Save**.
3. За хвилину-дві система відкриється за адресою `https://ВАШ-ЛОГІН.github.io/НАЗВА-РЕПОЗИТОРІЮ/`.

## Перший запуск

1. Відкрийте адресу сторінки. Система запропонує створити адміністратора: вкажіть логін, ім’я та пароль.
2. У розділі **Користувачі** зареєструйте працівників і призначте ролі: адміністратор, редактор, читач.
3. Щоб перенести дані з версії в Claude: там у розділі **Резервна копія** завантажте копію, а тут відновіть її. Облікові записи користувачів із копії не переносяться, бо паролі тепер зберігає Firebase; створіть їх заново.

## Безпека

- Ролі перевіряє сервер Firebase за правилами з `firestore.rules`, а не лише сторінка. Читач не може змінити дані навіть в обхід інтерфейсу.
- Особисті чати бачать лише учасники розмови й адміністратор (адміністратору це потрібно для резервної копії). Теми форуму бачать усі користувачі.
- Значення в `firebase-config.js` не секретні: так влаштовано Firebase. Без облікового запису в системі вони не дають доступу до даних.
- Список логінів користувачів доступний без входу (він потрібен для форми входу). Паролі та дані — ні.
- Адміністратор не може видалити обліковий запис із Firebase Authentication зі сторінки. Після видалення в системі запис втрачає будь-який доступ, а за потреби його можна прибрати вручну в **Authentication → Users**.

## Обмеження безкоштовного тарифу Firebase (Spark)

Приблизно 50 000 читань і 20 000 записів на добу, 1 ГБ даних. Кожне відкриття сторінки читає всю базу один раз, тож для кількох десятків працівників цього достатньо. Поточне використання видно в **Firestore Database → Usage**.
